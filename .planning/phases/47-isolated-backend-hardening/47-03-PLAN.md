import re  # already imported

class SerializeLogRecord(Serialize):
    @staticmethod
    def _redact_sensitive(message: str) -> str:
        """
        Scrub credential patterns from a log message string before it reaches
        the SSE stream.
        """
        # LFTP: -u username,secretpass  →  -u username,**REDACTED**
        message = re.sub(r'(-u\s+\S+,)\S+', r'\1**REDACTED**', message)
        # Generic: password=secret  /  password: secret (case-insensitive)
        message = re.sub(

            flags=re.IGNORECASE
        )
        return message

Extend the `_redact_sensitive()` static method in `serialize_log_record.py` with two new regex patterns, placed AFTER the existing password redaction patterns.

**Pattern A — sftp:// URL redaction (covers LFTP connection strings):**
```python
# SSH topology: sftp://user@host URLs (LFTP connection strings)
message = re.sub(r'sftp://\S+@\S+', 'sftp://**REDACTED**@**REDACTED**', message)
```
This matches `sftp://user@seedbox.example.com/path` and replaces the entire URL after `sftp://` with redacted tokens.

**Pattern B — user@host tokens in SSH/SCP command output:**
```python
# SSH topology: user@host tokens (preceded by whitespace/quote/bracket, not mid-word)
# Covers: 'user@host', "user@host:path", lftp user@host:~>
# Does NOT match: file@720p.mkv (@ preceded by word char 'e', not whitespace)
message = re.sub(
    r"(?<=[\s'\"\[])(\w[\w.\-]*)@([\w.\-]+)",
    '**REDACTED**@**REDACTED**',
    message
)
```

**Why this combination avoids false positives (LOG-03):**
- Pattern A is scoped by the `sftp://` prefix — only matches LFTP URLs.
- Pattern B uses a **lookbehind** `(?<=[\s'"\[])` requiring the token to be preceded by whitespace, quote, or bracket. This is the critical safety mechanism:
  - `"file@720p.mkv"` — the `@` is preceded by `e` (word char), NOT whitespace/quote → NO match → NOT redacted. Correct.
  - `"'myuser@seedbox.example.com'"` — the `@` is preceded by space inside the list repr → matches → redacted. Correct.
  - `"/downloads/show@720p/file.mkv"` — the `@` is preceded by `w` (word char) → NO match. Correct.
  - `"lftp myuser@seedbox.example.com:~>"` — the `@` is preceded by space → matches → redacted. Correct.

**Pattern ordering matters:** Pattern A runs first to handle sftp:// URLs completely. Pattern B handles remaining bare user@host tokens in SSH/SCP command output.

The updated `_redact_sensitive()` method should look like:
```python
@staticmethod
def _redact_sensitive(message: str) -> str:
    # LFTP: -u username,secretpass  →  -u username,**REDACTED**
    message = re.sub(r'(-u\s+\S+,)\S+', r'\1**REDACTED**', message)
    # Generic: password=secret  /  password: secret (case-insensitive)
    message = re.sub(
        r'(password[=:]\s*)\S+', r'\1**REDACTED**', message,
        flags=re.IGNORECASE
    )
    # SSH topology: sftp://user@host URLs (LFTP connection strings)
    message = re.sub(r'sftp://\S+@\S+', 'sftp://**REDACTED**@**REDACTED**', message)
    # SSH topology: user@host tokens (preceded by whitespace/quote/bracket, not mid-word)
    message = re.sub(
        r"(?<=[\s'\"\[])(\w[\w.\-]*)@([\w.\-]+)",
        '**REDACTED**@**REDACTED**',
        message
    )
    return message
```
